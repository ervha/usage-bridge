# usage-bridge（日本語）

[English README](README.md)

[ダウンロード](https://github.com/ervha/usage-bridge/releases/latest) · [変更履歴](CHANGELOG.md) · [問題を報告](https://github.com/ervha/usage-bridge/issues)

**AIエージェントに聞くだけで、各種サブスクの「残りトークン」をまとめて管理できる。**

Claude Code / Codex / Antigravity / Grok など、AIコーディングのサブスクはそれぞれセッション・週次の上限とリセット時刻がバラバラで、確認先も分散しています。usage-bridge を入れると、エージェントがその全部を一つの窓口で見られるようになります。

- **聞くだけで、まとめて確認。** 「今週の Claude の残りは？」と聞けば、エージェントが各サブスクの残量・リセット・ペースをまとめて答えます。ダッシュボードを巡回する手間が消えます。
- **MCPの連携先では、残量に沿って自動選択。** T3 Code のように、自前の MCP からは残量を読めないオーケストレータでも、残っている枠から先に使う、貴重な枠は難しい問題のために温存する、といったモデル選択を自動でできるようになります。

usage-bridge は、Windows トレイ常駐アプリ [OpenTokenUsage](https://www.poweruserz.dev/)（複数AIの枠を一括表示し、ローカルAPIを持つ）の出力を、小さな MCP サーバーとして中継します。経路は [Tailscale](https://tailscale.com/) の tailnet 内だけ。ポート開放はしません。

## AIエージェントと一緒に導入する

多くの人は、AIエージェントに頼んで導入しています。シェルを使えるエージェントなら、下の手順はすべて実行できます。人間にしかできないのは3つだけです。Tailscale へのサインイン、各プロバイダへのサインイン、そしてトークンの受け渡しの開始（PC でコマンドを1つ実行して、8文字のペアリングコードを読み上げること）です。長期トークン自体をチャットに書くことはありません。受け渡しはペアリングで1回だけです。

完了の目安は、エンドポイントが応答すること、有効化したプロバイダが見えていること、そして現在の読み取り値を1つ言えること（例:「Claude の週次は13%、リセットは金曜4時」）です。

**任意: companion スキルもどうぞ。** [skill/SKILL.md](skill/SKILL.md) は、セットアップ後の使い方をまとめたものです。残量をいつ確認するか、どう見せるか、モデル選択へどう繋ぐか、トークンの扱いのルール。エージェントのスキルフォルダに入れる（または指示文に貼る）だけで、残量確認が習慣になります。

## 構成

```text
OpenTokenUsage（ローカルAPI 127.0.0.1:6736/v1/usage）
  → usage_bridge.py（Python標準ライブラリのみ、Bearer認証、5分キャッシュ）
  → Tailscale（私設網内のみ）
  → AIエージェントが残量を読んで、使うモデルを自動判断
```

**サーバー部分について。** このプロジェクトが追加するプログラムは `usage_bridge.py` の1つだけで、これがサーバーの役目をします。自分の PC（`~/usage-bridge`）の中でログオン時に起動し、PC の tailnet アドレスの8787番ポートで要求を待ち受けます。なぜ要るかというと、OpenTokenUsage の API は同じ PC の中からしか読めない（127.0.0.1）ので、別マシンで動くエージェントが直接届かないからです。このプログラムが、その間の橋渡しをします。要求が来たら、トークンを確認し、OpenTokenUsage へ聞いて、答えを返します（5分キャッシュ）。クラウドのサービスではなく、第三者も挟まりません。トークンがあるのは PC の OS の安全な保管場所（Windows は DPAPI、macOS はキーチェーン、Linux は Secret Service）とエージェントの秘密ストアだけで、ペアリングコードはプロセスのメモリ内にハッシュとしてだけ存在し、再起動で消えます。PC が止まっていれば、話しかける相手自体が存在しません。

## セットアップの手順（全OS共通）

以下の手順が導入の全工程です。利用者本人でも、AIエージェントでも、同じ手順で進められます。人間にしかできない箇所には（人間）と付けました。

1. **OSを判定**し、インストーラを選びます。Windows は `install.ps1`、Linux / macOS は `install.sh` です。
2. **前提を確認**します。Python 3.10+ が動くこと。使用量の取得元が入っていること（Windows ではインストーラが OpenTokenUsage を winget で追加できます）。（人間）Tailscale のサインインはエージェントには代行できません。未サインインのまま導入すると `127.0.0.1` のみの待ち受けになるので、サインイン後にインストーラを再実行して tailnet アドレスへ張り替えます。
3. **ファイルを取得**します。最新リリースの zip を展開するか、このリポジトリを clone して、そのフォルダで作業します。
4. **インストーラを実行**します（冪等。再実行して構いません）。サーバーの配置（既定は `~/usage-bridge`、Windows は `%USERPROFILE%\usage-bridge`。変更もできて、Windows は `-Dest <path>`、Linux / macOS は `USAGE_BRIDGE_HOME=<path>` で指定します。その場合トークンの保管場所や自動起動の登録もそのフォルダ側になります）、トークンの作成（初回のみ OS の安全な保管場所へ。以後は保持され、古い `token.txt` があれば安全な保管場所へ移行します）、tailnet アドレスへの待ち受け、自動起動の登録、ヘルスチェックまで行われます。
5. **ローカルで確認**します。`GET http://<tailnet IPv4>:8787/health` が `{"ok": true, "service": "usage-bridge"}` を返すこと。`127.0.0.1` に張られている場合は Tailscale のサインイン不足です。先にそちらを直してください。
6. **トークンをペアリングで受け渡します。**（人間）PC で `python ~\usage-bridge\usage_bridge.py --pair`（Linux / macOS は `python3 ~/usage-bridge/usage_bridge.py --pair`）を実行し、表示される8文字のコードをエージェントへ伝えます。エージェントは `POST http://<tailnet IPv4>:8787/pair/redeem` に `{"code": "..."}` を送り、返ってきたトークンを秘密ストアに保管します。コードは10分有効・1回限りで、間違いが続くと失効します。トークン自体をチャット、ログ、コミット、スクリーンショットに出してはいけません。
7. **エージェント側のマシンから MCP を確認**します。
   - `initialize` でサーバー名 `usage-bridge` の応答が返ること
   - `tools/call` の `usage_all` で、有効化済みプロバイダの使用率を含むスナップショットが返ること

   401 はトークンの不一致。空応答やタイムアウトは、PCのスリープ、サーバー未起動、tailnet の不一致を疑い、行き当たりばったりの試行の前に「トラブルシュート」を確認してください。
8. **エージェントの MCP 設定へ登録**します。`POST http://<tailnet IPv4>:8787/mcp`、ヘッダー `Authorization: Bearer <token>`。トークンはコミットされる設定ファイルではなく、秘密ストアに置きます。
9. **割り振り方を決めます。** どの枠を量の多い作業に使うか、どのモデルを何のために温存するか、絶対のルールはあるか。companion スキルを使うエージェントは、初回に一度だけこの質問をして、答えを割り振りポリシーとして記録します。以後のモデル選択はそのポリシーに従います（[skill/SKILL.md](skill/SKILL.md) も参照）。

安全のための注意:

- 8787 のポート開放は絶対にしないこと。待ち受けは tailnet アドレスか `127.0.0.1` のみです。
- トークンはパスワード同等に扱ってください。
- このブリッジは読み取り専用です。値を「直す」ために PC 側へ何か書くことはありません。
- 同じ手順で2回失敗したら、インストーラの出力とトラブルシュートの該当行が原因をほぼ特定できます。

## 導入（Windows）

### 0. 事前準備

- 先に Tailscale へサインインし、`tailscale ip -4` で tailnet IPv4（100.x…）を確認してください。サインイン前に導入すると `127.0.0.1` のみの待ち受けになるので、その場合はサインイン後に導入をやり直してください。
- PowerShell で `python --version`（または `py --version`）が通ることを確認してください。

### 1. ファイルの取得

最新リリースから `usage-bridge-v1.0.0.zip` をダウンロードして展開し、そのフォルダで PowerShell を開いてください。

### 2. インストーラの実行

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

OpenTokenUsage と Tailscale の導入、サーバーの配置（既定は `%USERPROFILE%\usage-bridge`。`-Dest <path>` で変更でき、アンインストーラも同じ `-Dest` を受けます）、トークンの作成（`--init-token` で Windows DPAPI の安全な保管場所へ。トークン自体は表示されません）、tailnet アドレスへの待ち受け設定、スタートアップフォルダへの自動起動登録（管理者権限不要、pythonw で窓なし起動）、ヘルスチェックまで一括で行います。再実行時は古いサーバープロセスを先に止めるので、古い版がポート8787を掴んだままになることはありません。トークンの受け渡しはペアリングで行います（セットアップの手順を参照）。

### 3. プロバイダの有効化

OpenTokenUsage を一度開き、使うプロバイダ（Claude / Codex / Antigravity / Grok など）を有効化して、サインイン状態を確認してください。

### 4. 動作確認

```powershell
Invoke-RestMethod http://<tailnet IPv4>:8787/health
# → {"ok": true, "service": "usage-bridge"}

# 認証ありの確認: トークンは OS の安全な保管場所にあり、読めるファイルには
# ありません。エージェントと同じくペアリングで受け取ってください
#   python ~\usage-bridge\usage_bridge.py --pair   でコードを発行し、
#   POST /pair/redeem に {"code": "..."} を送るとトークンが1回だけ返ります。
# 受け取ったトークンを Authorization: Bearer <token> として /usage を呼びます。
```

エージェント側のマシンからも `/health` が返れば、経路まで完成です。`/usage` で 401 になる場合はトークンの不一致、タイムアウトする場合は PC のスリープ、サーバー未起動、tailnet の不一致を疑ってください。

## 導入（Linux / macOS）

### 0. 事前準備

- 先に Tailscale へサインインし、`tailscale ip -4` で tailnet IPv4 を確認してください。未サインインだと `127.0.0.1` のみの待ち受けになります。
- `python3 --version` が通ることと、使用量の取得元が起動して `127.0.0.1:6736/v1/usage` を出していることを確認してください（OpenTokenUsage は Windows 専用なので、Linux / macOS では OpenUsage など同等の取得元が要ります）。
- `sudo` は不要です。すべてホームディレクトリの下に入ります。

### 1. ファイルの取得とインストーラの実行

最新リリースの zip を展開するか、このリポジトリを clone して、そのフォルダで実行します。

```sh
sh ./install.sh
```

サーバーの配置（既定は `~/usage-bridge`。`USAGE_BRIDGE_HOME=<path>` で変更でき、アンインストーラも同じ変数を見ます）、トークンの作成（`--init-token` で OS の安全な保管場所へ。macOS はキーチェーン、Linux は Secret Service、無い環境では `token.txt` 権限600に fallback。トークン自体は表示されません）、tailnet アドレスへの待ち受け設定、自動起動の登録（Linux は systemd ユーザーサービス、macOS は launchd エージェント）、ヘルスチェックまで一括で行います。再実行時は古いサーバープロセスを先に止めます。

### 2. 動作確認

```sh
curl http://<tailnet IPv4>:8787/health
# → {"ok": true, "service": "usage-bridge"}
curl http://<tailnet IPv4>:8787/usage \
  -H "Authorization: Bearer <ペアリングで受け取ったトークン>"
```

## 更新

新しいリリースの zip を展開して、インストーラ（Windows は `install.ps1`、Linux / macOS は `install.sh`）を再実行するだけです。トークンは保持され（古い `token.txt` は安全な保管場所へ移行されます）、古いプロセスの停止と自動起動の再登録まで自動で行われます。保存される状態は他にないので、移行作業はありません。

## 削除（アンインストール）

Linux / macOS では `sh ./uninstall.sh` を実行してください。サーバーの停止、自動起動の登録解除、`~/usage-bridge` の削除まで行います。その後、エージェント側の設定から MCP のエンドポイントを削除してください（下の手順4と同じです）。

Windows では `powershell -ExecutionPolicy Bypass -File .\uninstall.ps1` を実行してください。サーバーの停止、スタートアップ登録の削除、`%USERPROFILE%\usage-bridge` の削除まで行います。その後、エージェント側の設定から MCP のエンドポイントを削除してください。手作業でやる場合は以下の手順です。

1. サーバープロセスを止めます。

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name like 'python%'" |
     Where-Object { $_.CommandLine -like "*usage_bridge.py*" } |
     ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
   ```

2. スタートアップフォルダ（エクスプローラのアドレスバーで `shell:startup`）から `usage-bridge.cmd` を削除します。
3. `%USERPROFILE%\usage-bridge` フォルダを削除します（DPAPIで暗号化されたトークンファイルも一緒に消えます）。
4. エージェント側の設定から、この MCP のエンドポイントを削除します。
5. 必要な場合のみ、OpenTokenUsage と Tailscale を Windows の設定や `winget uninstall` で削除してください。usage-bridge 自体はレジストリ等に何も残しません。

## 負荷について

設計上、ほぼゼロに抑えてあります。

- **小さな Python プロセスが1つだけ。** 標準ライブラリのみで依存なし。メモリは約10MB、待機中の CPU は 0% です。
- **ポーリングしません。** エージェントが実際に聞いたときだけローカルAPIを叩き、結果は5分キャッシュします。エージェントが何度聞いても、上流への取得は1回で済みます。
- **ディスクへの書き込みなし**（ログは標準エラー出力のみ）。通信も tailnet 内で数KB程度です。
- OpenTokenUsage 自身はトレイ表示のために定期更新しますが、その負荷はこのブリッジの有無とは無関係です。ブリッジが追加する常駐負荷はありません。

## わざわざ使う価値

こんな人には割に合います。

- AIコーディングのサブスクを **2つ以上** 契約していて、どの枠が余っているか把握しきれていない。
- エージェントやオーケストレータに **モデル選択を任せている** のに、その判断が残量を見ずに行われている（空の枠を叩いたり、貴重な枠を雑に使ったりしている）。
- エージェントの実行マシンと、サインインしている PC が **別々** で、「トレイを見ればいい」が通用しない。

得られるのはダッシュボードではありません。枠の管理が人間の頭の中から消えることです。エージェントが使う前に残量を確認し、余っている枠から先に使い、貴重な枠を必要な仕事のために残すようになります。

逆に、サブスクが1つだけ、エージェントが自前の残量表示を持っていてモデルを切り替えることもない、サインインしている PC が普段ほとんど起きていない、といった場合は、部品が1つ増える割に得るものが少ないので、無理に入れなくて大丈夫です。

## トラブルシュート

- ヘルスチェックが失敗する → Python が PATH に無い、またはポート8787が使用中。再実行で古いプロセスは止まります。
- 「Tailscale IPv4 not found」と出る → Tailscale 未サインイン。サインイン後に再実行してください。
- エージェントから空の応答が返る → v1.0.0 で修正済み（pythonw 起動時の不具合）。古いコピーが動いていないか確認し、インストーラを再実行してください。
- 「OpenTokenUsage local API unreachable」と出る → OpenTokenUsage が起動していない、またはプロバイダが未有効化です。

## ツール

- `usage_all` — 有効な全プロバイダの使用量スナップショット
- `usage_provider` — 1プロバイダ分（例: `claude` / `codex` / `antigravity` / `grok`）

## 注意

- 8787番ポートをインターネットへ直接公開しないでください。
- 外部へ勝手に送信することはありません。データは tailnet の中で、聞いてきたエージェントへだけ返ります。テレメトリ類もありません。
- 引き換えに生まれるリスクもあります。トークンを持つ人（tailnet 内）には使用量のパターン（量・プラン・おおよその活動時間）が読めること、ペアリングコードは10分の有効期限内なら提示した人が交換できてしまうこと、読み取り値の正確さは OpenTokenUsage の非公式なローカルAPI次第であること。リスクの全文は [SECURITY.md](SECURITY.md) にまとめました。導入前に目を通してください。
- トークン未設定だと認証が無効になります。その場合は `127.0.0.1` のみに bind してください。
- 読み取り専用です。書き込み系ツールはありません。
- PCがスリープ中は届きません。OpenTokenUsage のローカルAPI形式はアプリ更新で変わる可能性があります。

詳細は英語版 [README.md](README.md) と [SECURITY.md](SECURITY.md) を参照してください。

## 近いプロジェクトとの違い

残り枠を返す MCP は他にもあります（agent-runway、tokenhud、ai-usage-mcp、tokenmeter-tray など）。ただ、OpenTokenUsage を取得元にするもの、別マシンで動くエージェントが Tailscale 越しに読む前提のものは、調べた範囲では見つかりませんでした。違いは3点です。

1. 取得元 — 各社を自前で叩かず、OpenTokenUsage が集約済みの枠（Antigravity や Grok を含む）を使う
2. 構成 — サインインのある PC とエージェントが別マシンでもよい
3. 目的 — 人間が見るダッシュボードではなく、T3 のモデル選択に渡すこと
